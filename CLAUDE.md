# CLAUDE.md

Guide for AI coding agents working in this repository. Humans: see `docs/HANDOVER.md` and `CONTRIBUTING.md`.

## Keep the handover current (every change)

TouchLine is built by two people, the owner and a friend, each working with their own AI coding agent. These documents are the shared memory between those agents, so they are only useful if every change keeps them true.

- **Before you start:** read `docs/HANDOVER.md` (the in-progress table and the change log) and the open GitHub issues, and pick or claim an issue so the other person's agent does not build the same thing.
- **In the same pull request as your change**, update:
  - `docs/HANDOVER.md`: the in-progress table when work starts, moves branch or finishes; "What it does today" when a feature ships; hosting and backend notes when a service, environment variable or setting changes; known issues when you find or fix one; and one dated line in the change log at the bottom (date, who or which agent, what changed, PR or issue link).
  - `CLAUDE.md`: whenever a command, path, invariant or convention changes (for example a new module, a renamed script, a new `ENGINE_VERSION` value).
  - `CONTRIBUTING.md`: whenever the way the two of you work together changes.
- A pull request that changes behaviour without touching `docs/HANDOVER.md` says why in its description. The pull-request template has a checkbox for this.
- Never delete another person's change-log lines; add your own below them.

## What this is

- **TouchLine** (written with a capital L) is a browser football game: 38-0's spin-the-wheel draft fused with Football Manager depth.
- A wheel lands on a real club in a real season (seven leagues, 2008-09 to 2026-27); you draft one player per spin, then simulate or manage the season.
- Stack: Vite 6 + React 19 + TypeScript 5.8 strict + Zustand 5 (persist) + Immer 11, icons from `lucide-react` (pinned). Tests: Vitest 3 (node environment).
- A deterministic seeded engine (`src/engine`) is the core: one seed replays identically on every device (the Daily, challenge links, leaderboards).
- No server at runtime: static JSON league packs in `public/data`, saves in `localStorage`. An online layer on Supabase is in progress and must stay optional.

## Invariants (do not break)

1. **Determinism.** No `Math.random`, `Date`, `Date.now` or `performance.now` in `src/engine` or in `src/game/logic` simulation paths. Every random draw goes through an `Rng`: `const rng = Rng.fromState(game.rngState); ...; game.rngState = rng.getState()`. Never `new Rng(...)` mid-game (only `createGame` and `startH2H` seed; `createGame` also seeds an arena game's three streams, `${seed}#field`, `#ties` and `#draw`, in `Game.arena.streams`, which draw the field so it never depends on the draft). Allowed exceptions: `randomSeed()`, `dailySeed()`, `arenaDailySeed()` and `weeklySeed()` with no argument, game ids/`createdAt`, achievement and leaderboard dates; `newDraft` and `unpackPowerUp` seed a draft's side streams from the game seed (`${seed}:powerups` and the like). The manager spin and the end-of-draft case draw from `Rng.fromState(game.rngState).fork(label)` and never write the state back (labels `manager-spin`, `end-case`): keep it that way, or bump. UI randomness (reel cosmetics) never feeds the game.
2. **ENGINE_VERSION.** Bump `src/engine/version.ts` in the same commit whenever a change alters how many draws, or in what order, a spin, pick, match, season, cup draw, market day or event takes, or retunes a constant that changes a replayed outcome. Add a line to `docs/GAME_DESIGN.md` section 15 naming what the previous value meant. Re-baseline seeded tests in that commit.
3. **Data order is seed meaning.** `mergeUniverses` concatenates packs in `leagues.json` order. Append new leagues at the end; never reorder. Club ids and player-season ids (`${playerId}@${season}@${clubId}`) are permanent.
4. **Never change the Daily mapping** (`dailySettings`, `DAILY_FORMATIONS` order, `DAILY_RULES`, `DAILY_SEASON` and `DAILY_EPOCHS` in `src/game/logic/daily.ts`, `dailyGameSettings` in `src/game/logic/setup.ts`). The Daily's league comes in dated epochs, like the Weekly (`DAILY_EPOCHS`, `dailyLeagueOf`, `dailyPlan`): the Premier League before 2026-10-30, then the seven leagues one a day; a new rotation goes in a new epoch from a future day, never an edit to a shipped one (`dailyRotation.test.ts` pins every date before it byte for byte). A new draft rule gets a literal value in `DAILY_RULES` (a test fails until it does). Nor the Daily Arena's (`dailyArenaSettings` in `src/game/logic/arenaDaily.ts`), the Run-in of the week's (`weeklyRunInPlan`/`weeklyRunInJob` in `src/game/logic/runinWeekly.ts`) or the Weekly's (`weeklyPlan`/`weeklySettings` in `src/game/logic/weekly.ts`, `WEEKLY_THEMES` ids and `WEEKLY_EPOCHS` in `weeklyThemes.ts`). A new weekly theme goes in a new epoch from a future week; never edit a shipped epoch.
5. **Save compatibility.** New fields on anything persisted (`Game`, `GameSettings`, `Profile`, `Contract`, `DraftRules`, `DraftState`, `SeasonState`, `SquadPlayer`, `MatchInProgress`, `Tactics`, market types) are optional and read with `??` / `??=`. Defaults that must exist go in `normaliseGame` (`src/game/logic/save.ts`). Do not rename or retype fields. Do not change `SAVE_KEY` or persist `version: 1` without a `migrate`; doing so wipes every save. Keep `Game` JSON-serialisable (no Map, Set, class instances, functions). ## Adding a feature end to end

1. **Engine** (`src/engine`): pure function over plain data plus an `Rng`. New persisted fields optional. Bump `ENGINE_VERSION` if draws change.
2. **Game logic** (`src/game/logic/*.ts`): `fn(game, u, ...)` mutating `game` in place, RNG rehydrated and written back. Weekly behaviour hooks into `afterMatchweek` in `week.ts`; check both the live path and `playMatchweek(..., true)`.
3. **Store action** (`src/game/store.ts`): declare it on the `Store` interface, implement as `mutate((g, u) => { logicFn(g, u, args) })`. If it can end a season, call `unlockFromGame()` and `recordResult()` after, as `playWeek` does.
4. **UI** (`src/ui`): render and call the action. Keep diffs local; add `data-testid` hooks for smokes.
5. **Tests**: Vitest in `src/engine/__tests__` or `src/game/__tests__`; extend the old-save test in `src/game/__tests__/audit.test.ts` for new save fields.
6. **Docs**: README feature line, `docs/GAME_DESIGN.md` section, ENGINE_VERSION history if bumped.
7. **Verify**: typecheck, test, build, smoke.

Specific recipes: a draft rule (optional `DraftRules` field, apply in `rulesPool`/`canUse`, `RULE_CHECKS`, thread through `GameSettings` and Setup, a 200-seed no-dry-wheel test); a twist (extend `Twist`/`TWISTS`, `twistAllows`, bump); an event (candidate in `rollEvent`, case in `resolveEvent`, apply in `applyEventChoice`, bump); a Dugout tab (`DugoutTab` in `briefing.ts`, `Tabs` array in `Dugout.tsx`).

## Gotchas

- Never break a tie with a bare `localeCompare` in the engine or in game logic that reaches a result: it collates in the device's language (Lithuanian puts "y" between "i" and "j"), so a table or a pick could split differently on two devices and in the verifier. Use `compareText` (`src/engine/rng.ts`, English); `src/engine/__tests__/auditFixes.test.ts` simulates a Lithuanian device. Display-only sorts (a list of names) may follow the viewer's language.
- A quick season with a bench (`DraftRules.benchPicks`) is played again on every bench change, from `Game.quickStartRng` (where it kicked off), never from `game.rngState`, which `runQuickSeason` leaves at the end of the season. Its result is recorded on `endPlayback`, not at kick-off (`Game.quickOpen`). Bench spins after the XI draw from `DraftState.benchRng`, not the game's stream; keep both so a bench changes nothing until it is used.
- Rebuilding data changes `leagues.json` `generatedAt`: update the pinned stamp in `universe.test.ts` and record the stamp in `src/online/__tests__/packHashes.json` (command above); old challenge links read as unverified. Deploy engine bumps and data rebuilds right after 00:00 UTC so a day's Daily pin and the live site agree. An engine bump is best released right after 00:00 UTC on a Monday: a week's Weekly is pinned once on the engine of its first ranked request, so a mid-week bump leaves that week's ranked Weekly on the old function and the new one refuses its posts (`engine_mismatch`) until the next Monday. `universe.test.ts` and `records.test.ts` assert real facts and can break on a rebuild with no code change.
- Cup ties take the week's `rng` (engine 7): `completeUserCupTie(game, u, rng, ...)` no longer rebuilds from a stale `game.rngState` inside `afterLeagueMatch`. Pass `rng` down rather than adding more `Rng.fromState` calls.
- The Continental Cup has two formats in saves: `continental.groups` present (engine 7: `continentalMidweek`/`closeContinentalWeek` in `week.ts`, `LiveMatch.group`/`leg`) or absent (engine 6's single-tie knockout through the shared cup flow). Screens read a tie's score with `tieScore`, never `t.result` alone (a second leg's `result` keeps that match's own sides, the tie's away side at home).
- A sent-off or injured man stays in his slot inside `advanceMatch`; `shortHandedFactor` costs it. Do not "fix" it.
- The late fade (`applyLateFade`) is applied once, when `advanceMatch` plays 71-90, and stored as `TeamSnapshot.lateFadeAt70`; `changeInPlay` after 70 re-applies the stored value to the expected goals only. Never call `applyLateFade` again in a cut.
- An untouched match must equal `simulateMatch` event for event however the dashboard pauses it: `changeInPlay` refuses a change that changes nothing before touching `mp` (tested over 40 seeds × 10 minutes).
- `simulateMatch` must equal `beginMatch` -> `advanceMatch(70)` -> `finishMatch` event for event (tested).
- Formation slot ids are keys of saved lineups, roles and challenge picks; never rename them. Role contributions sum to 1.
- `store.merge` spreads persisted state over defaults, so removing a persisted key needs handling in `merge`.
- `go()` clears `pendingChallenge`; navigating away from Setup drops an opened challenge link.
- Theme: `data-theme` is always set (`light` or `dark`), by the inline script in `index.html` before load and by `App.tsx` after; Auto follows `prefers-color-scheme` live. Headless Chromium reports light, so smokes on Auto run in Daylight unless the context sets `colorScheme: 'dark'`.
- `Rating` (`bits.tsx`) renders the number as a bare text node inside `.rating`, and no CSS hides it: always pass `hideRatings`/`hidden`, from `ratingHidden(rules, place)` (`src/game/logic/ratingVisibility.ts`). The old `.hidden-ratings` class and its rules are gone (r8 audit; blind mode shows the user's own squad).
- Motion: every new animation goes on the `--dur-*`/`--ease-*` tokens, animates transform or opacity only (never `left`/`top`: a man placed in per cent of a box moves by a transform in `cqw`/`cqh`, as the match day's formation men do) and is added to the reduced-motion block at the end of the motion section in `styles.css`. A `.page` with a fixed bottom bar must carry `.has-bottom-bar` (it then only fades: a transform on `.page` would carry the bar). `CountUp` sets `data-counting` while it climbs; a smoke that reads `.record` or the Points stat waits for it to go.
- Type sizes are `--fs-*` tokens; a `font-size: Npx` in `src/ui/**/*.css` needs a `/* px: why */` note on its line (text drawn to a fixed geometry), or `src/ui/__tests__/cssGuards.test.ts` fails CI. The same test fails on a `left` or `top` transition.
- Reel timing lives in `src/ui/reelCurve.ts` (re-exported by `CaseReel.tsx`): `FULL_TIMING` with `DRUM_MS` 850, `SEASON_MS` 1000 (when the strip starts), `SPIN_MS` 5800 (the slide, its 200 ms ease back from the overshoot included) and a 400 ms hold, so `SETTLE_MS` (the reveal and `onSettled`) is 7200 and is derived: change `SPIN_MS` and the hold together with the measurements in `docs/GAME_DESIGN.md` section 4; `QUICK_TIMING` (2 s slide, about 2.7 s to the reveal) for re-spins and the per-viewer Quick spin (`touchline-quick-spin`). The slide is keyframed from `reelPosition` (`STRIP_CURVE`, `OVERSHOOT`) and the ticks come from the same function (`src/ui/sound/schedule.ts`), tested in `src/ui/__tests__/sound.test.ts`. Smokes should wait on `.reel-run[data-stage="landed"]` (up to about 8 s, or skip with `reel-skip`), not a fixed sleep.
- Sound plays only after a gesture and never where `AudioContext` is missing; keep it that way (the autoplay policy, the tests, headless runs). The unlock takes only trusted events and waits for `navigator.userActivation.hasBeenActive`, and Playwright's `page.evaluate` counts as activation, so a "no gesture" smoke counts the contexts made after scripted clicks rather than reading that flag. A new sound is a score in `src/ui/sound/scores.ts` (or, for a cue that need not be in the first download, `voices.ts` with its id in `cues.ts`) played with `playSound(request)` (or, kept out of the first download, a score in a sibling such as `seasonScores.ts` played with `playScore`), never raw nodes in a component; it follows a category switch (`CUE_CATEGORY`/`CATEGORY`) and, if it can repeat quickly, a gap in `CUE_GAP_MS`; match sounds go through `match.ts` from the live clock, not timers. Smokes with a recorder can tell the referee's whistle by its carrier's first frequency (2950 × 0.92 Hz; a card's peep is 1.02 × that).
- One typeface, Sora (Google Fonts, OFL), linked in `index.html` and named by both `--font-display` and `--font-body`; `shareCard.ts` names it for the canvas and waits for `document.fonts`. The lockup's name geometry (`LOCKUP.name` in `brand.ts`, the `.tl-*` rules, `brand.test.ts`) is tuned to Sora's metrics (cap 0.73, x-height 0.55, baseline 0.84 of the size): change the three together if the face changes.
- `public/sw.js` must keep the literal `__BUILD__` (stamped at build), the literal `'__ASSETS__'` (the stamp plugin in `vite.config.ts` replaces it with every `./assets/` file, precached at install) and relative paths. `index.html`'s inline script preloads `data/leagues.json` and England's `meta.json`/`players.json` only on a page no service worker controls (Chromium never matches a preload on a controlled page); keep pack fetches on `fetch`'s default mode and credentials so the preloads match. Packs are unhashed and served stale-while-revalidate, so pack-shape changes must tolerate one old visit.
- `*.tsbuildinfo` is gitignored and `tsconfig.app.tsbuildinfo` is no longer tracked (`tsconfig.node.tsbuildinfo` still is): a branch that still commits the app file conflicts as modify/delete; resolve with `git rm --cached tsconfig.app.tsbuildinfo` and rebuild.
- The Dynasty summer's bonus spins stop at `SQUAD_CAP` (`dynasty.ts`), and `signYouth` checks `SQUAD_CAP` (engine 6; `youth.ts` is in the edge verifier's bundle through `setup.ts`).
- AI sides never move their morale, familiarity or form (`applyMatchToAiState`): a new AI state change goes through it, or managed leagues drift again (engine 5 reached 3.7 goals a game). A new AI side builder or match path passes the user's humans (`taken`) and plays AI against AI through `aiFixtureInputs`; `bothSides.test.ts` wraps the match engine and fails on any man on both sides.
- An AI side may field its reserve keeper (`reserve-gk-<club>@<season>@<club>`), who is not in `u.index`: resolve a match's men with `aiLookup(u)` or `playerLookup(game, u)`, never `u.index[id]` alone.
- `cabinet.ts` is in the edge verifier bundle's module graph (through `quickCups.ts`): even a change that tree-shakes away (a new import, new functions using new symbols) renames the bundle through esbuild's identifier minifier. Add Trophy Room logic in a module of its own that wraps it, as `feats.ts` does.
- The edge verifier bundle (`dist/edge/verifier-<hash16>.js`) takes in every `src/game/logic` module `playSeason` reaches, `endCase.ts` and `slotSheet.ts` among them: a display-only change there still renames the bundle and needs a loader redeploy. Put display helpers in their own module (as `slotRating.ts`, `oddsDisplay.ts`, `draftTurn.ts`) and check the name after `npm run build`.
- The Super League (`DraftRules.superLeague`) reads its AI sides through `quickLeague` (`src/game/logic/superLeague.ts`): a new quick-season consumer of the league's clubs (odds, cups, a replay) must call it, not `buildAiClubs`, or it plays the real league. Its field depends on the leagues loaded, so it needs all of them (`leaguesFor`, `openChallenge`); it is keyed by club id, one season per club. Name its sides with `sideNamer`, not `clubName`. `superLeague.test.ts` pins non-Super games to hashes of the commit before it.
- Quick Draft managers (`QUICK_RULES.managers: true`) change a default quick season's result (the first manager offered is settled at kick-off) without drawing anything; a test that pins a quick season's outcome either sets `managers: false` or calls `settleManager` as `toKickoff` does. Never add a draw to the manager path: off must stay identical to before.
- `finishSeason` parses `awards.goldenBoot.value` as `"<n> goals"`; changing award strings breaks achievements.
- France, the Netherlands and Portugal have no tables (no record book, flat wheel weight).
- England's classic seasons (1992-93 to 2007-08) are in `meta.seasons` with `classic: true`, `ratingsSource: 'estimated'` and `appsSource` (share of club-seasons with a real appearances table); `historicTables` no longer holds them; the first three have 22 clubs and 42 games, so anything that assumes 20 clubs or 38 games per historic season is wrong. A table row's `points` is net of `deduction`; `u.voidTitles` lists seasons with no champion (none shipped today).
- The classic pack (`england/players-classic.json`) is not loaded at start (`src/game/packs.ts`): only a game with `rules.classic`, the Classic toggle and Explore load it. A new screen or path that shows or plays classic seasons calls `ensureClassic()` (or `ensureLeagues(ids, true)`) first; a pool that reads `u.clubSeasons` without the opt-in sees the same universe either way.
- Lazy screens (`lazyScreens.tsx`): a new screen goes in App.tsx's `SCREENS` table (wrapped in `withRules` when it plays or shows a game), never a static import (`budget.test.ts` fails on one); its chunk is prefetched after Home and cached by the service worker. On a touch screen the lockup's flutter (`TOUCH_WAVE_LOOPS`, counted once per page load by `touchWaveOn`, not per mount) and Home's neon light stop after three loops: an infinite SMIL or dash-offset animation repaints the page every frame on a phone (docs/PERFORMANCE.md).
- The data stamp is a date, so two rebuilds on one day share `generatedAt`: a challenge link made on the first reads as verified on the second even when the packs changed.
- The docs were brought to engine 6 and the public repository on 2026-10-27 (`claude/r7-docs`) and to engine 7, the Daily rotation, round 8 and accessibility round 4 on 2026-10-29 (`claude/r9-docs`), and checked against the code at round 12 on 2026-10-29 (`claude/r13-docs`): README is the public front page (play link, screenshots, credits, the licence line: all rights reserved until the owner chooses one; never add a licence file), `docs/FEATURES.md` holds the long feature list, `docs/GAME_DESIGN.md` every system, and How it works (`src/ui/screens/HowTo.tsx`, catalogue `src/ui/i18n/en/howto.ts`) the in-game summary. Keep them true as you go.
